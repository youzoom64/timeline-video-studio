# 効果音の使用

効果音の記録と作品への採用を分けて進める。音源DBは将来の動画やゲームにも使えるよう、音そのものの記述を正本にする。

## 配置前にシーン別の案を書く

1. 依頼の対象範囲を確認し、編集JSONからオブジェクトの登場、位置・倍率・回転などの変化、画像の差し替えと、その開始・終了時刻を抽出する。発話と対象の役割を照合し、追加・置換・外す・現状維持の案を決める。画像と再生は、抽出した変化の見え方と同期の確認に使う。
2. 対象範囲のシーンを順に並べた設計表を作る。各音に「対象の発話・オブジェクトID」「鳴らす理由と役割」「同期するパラメータ・開始または完了・時刻」「長さ・音色・強さ・余韻」を書く。音を使わないシーンにも、その理由を記す。説明そのものに前提の不足がある場合は、説明の補足案を先に扱う。
3. 設計した特徴をDBの検索文にする。例えば動きの終点を控えめに示すなら「小さな単発音、丸い音色、明瞭な立ち上がり、短い減衰」と表す。特徴の説明でベクトル検索し、DBにある長さ・カテゴリなどで候補を絞る。
4. 各用途に対して複数候補を取り出し、聴感音量をそろえて元音源を比較試聴する。「候補ID・元パス・聞こえた特徴・設計に合う点・採否と理由」を設計表へ残す。合う候補が得られるよう検索文や検索対象を見直す。
5. 設計表を時系列に読み、同じ意味の出来事には音の共通性を持たせ、異なる役割は聞き分けられるようにする。近接する同音の反復と音の密度を確認し、音の変更や挿入を外す案を検討する。
6. 設計が成立してから編集データへ配置し、映像・声・BGMと一緒に再生する。表示との同期、聞こえる大きさ、声への重なりを調整し、確認結果を残す。

設計表の項目は [references/scene-sound-plan.md](references/scene-sound-plan.md) を使う。シーン番号や音源の割り当ては各作品の設計書に保存する。「まず案まで」という依頼では設計書の作成まで進める。

## JSONの変化へ効果音を結び付ける

- 配置の基準は編集JSONにする。倍率の増減は伸長・縮小、位置の変化は移動、クリップの開始は登場・画像差し替えとして抽出し、発話と対象の役割から使う音を決める。
- 効果音に、対象のID、同期するパラメータ、変化の開始または完了、必要な時間差を記録し、配置時刻を現在の編集JSONから計算する。画像と再生は、見え方・意味の対応・音との同期の確認に使う。
- 同じ役割の変化には同じ配置規則を適用する。同時に一つの出来事を示す複数の要素は、一つの音にまとめる。写真の継続パンや字幕更新など、音を伴わない役割も登録する。
- 抽出した変化の一覧と配置済みの効果音を対象IDごとに照合し、同じ役割の変化への付け忘れと二重配置を確認する。
- 図の内部が一枚の画像に描かれている場合は、差し替える画像クリップの開始時刻を同期先にする。内部の要素を個別に制御する制作では、その要素を別オブジェクトとして配置する。
- 編集後は対応を再計算し、対象の削除・動きの消失・同時だった要素の時刻の分離を確認して、対象の効果音へ反映する。読み込み済み素材と再生データを再利用する。

Timeline Video Studioでは [references/timeline-json-events.md](references/timeline-json-events.md) のスクリプトで、JSONの変化の抽出と、登録した効果音の時刻の同期を行う。

## 音源を整理する

- 対象の全ディレクトリと件数を把握してから候補範囲を決める。見ていない音源を含めて「最適」と言わない。
- 音声AIに分析させる場合、送信する音声と質問文を確認する。汎用DBの分析では音の始まり、音色・響き、変化、終わり方を尋ね、特定作品での用途は質問に混ぜない。ファイル名を質問に入れる必要がなければ送らない。
- 元ファイルは変更しない。回答原文、使用した質問文、モデル、元音声のID・名前・絶対パスを対応づけて保存する。有料の一括再実行は、対象件数と質問文を明示した着手指示に従う。
- 回答に用途やジャンルの推測が混じっていても、後からその部分を切るだけで中立な分析になったとは扱わない。

## ベクター検索する

- 音の特徴を表す日本語の検索語からEmbeddingを作り、音源説明のベクトルと比較する。索引にはモデル名、次元、説明文のハッシュと音源IDを保存し、検索結果から元音声の絶対パスへ戻せるようにする。
- 検索結果には近さ、音源名、元パスを出す。検索順位は聴取の候補順であり、音の適合判定ではない。ファイル名やAIの説明だけで採用せず、元音声を聞く。
- 解析文の変更後は古いベクトルを流用せず再計算する。件数、IDの一意性、元パス、次元、検索結果を検証する。
- 既存の音源DBを使うときは [references/sound-library.md](references/sound-library.md) を読み、利用環境の検索ツールと元音声の所在を確認する。

## 場面で選んで使う

- 設計表の対象となる出来事に、音の立ち上がりや着地を合わせる。シーンの表示開始と、画面内の動作の開始・完了を区別する。
- 候補の聞き比べは、音そのものの比較と、ナレーション・BGMを含む場面内の比較を行う。設計表に照らし、声や重要な数字を聞き取れる音を選ぶ。
- 編集データには元音源のパス、使用区間、開始時刻、音量、フェード、対応する発話・画面要素を残す。仮音と採用音を区別する。
- 配置後は音声付きの該当区間を再生し、発話・表示との同期、聞こえる大きさ、連続する効果音の重なりを確認する。実際に聞く前に完成扱いしない。
