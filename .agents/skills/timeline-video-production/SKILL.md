# 動画制作

ユーザーの題材と目的を起点に、必要な工程を進めて再生可能な動画と編集可能なプロジェクトを渡す。相談だけを求められた段階では構成案を示し、制作指示が出たら完成物まで進める。尺や表現の方向は依頼ごとに決め、過去の60秒デモを標準扱いしない。

## 制作の流れ

1. 主題と視聴者を整理し、動画全体で何を理解してもらうかを決める。ユーザーが指定した筋や承認した台本を保持し、尺は説明に必要な長さから考える。
2. 実在の出来事や現状を扱う場合は一次資料を優先して調査し、裏付けのある事実、解釈、未確定の点を分ける。既存作品は正本と既存素材を確認する。調査を求められていない構成相談では先回りして検索しない。
3. 台本を組み立てる。視聴者の疑問、説明によって分かること、そこから生まれる次の疑問を一本につなぐ。
4. 素材の量産と制作JSON化の前に、全編の見せ方とラフな絵コンテを作る。各カットに発話、画面に見えるもの、画面内の変化、次へ移る理由を対応づけ、並べて見直す。
5. 見せ方の異なる区間とそのつなぎを、仮素材で連続した仮編集にする。理解できる速さ、情報量、単調な反復を確認し、問題があれば全体構成や絵コンテへ戻る。
6. 構成と仮編集が成立してから、必要素材を取得・生成し、制作JSONへ落とす。既存素材は内容を確認して再利用する。音声は下記の手順で作り、完成した発話に映像と字幕を合わせる。仮編集用JSONの作成は必要に応じて行ってよい。
7. Timeline Video StudioのAPIで本編集し、音声付きの連続再生と実フレームで確認してMP4を書き出す。出力後は `ffprobe` 等で長さ、映像、音声を確認し、MP4と編集用JSONを渡す。ユーザーが指定した工程までを作業範囲とする。

## 全体構成と絵コンテ

台本の章や小見出しを、そのまま一つの画面へ割り当てない。一つの説明を複数カットで追うか、一枚を保って読ませるかを、その内容に応じて決める。

区間ごとに、実物を見る、数字を比較する、具体的な出来事を追う、仕組みをほどく、考えるために止まるなど、理解に必要な見せ方を選ぶ。写真の枚数、同じ画面の型、一定秒数ごとの切り替えを先に決めない。

全編の絵コンテを順番に並べ、隣接するカットの構図、情報量、表示順、進行速度を確認する。説明上の理由がない反復は、カットの分け方や説明のまとめ方から直す。写真の挿入、色替え、動きの追加だけで済ませない。文字サイズなどの共通仕様を保ちながら、内容に応じて画面構成を変える。

単独の完成画像や一覧画像だけでテンポを判断しない。見せ方の異なる区間とそのつなぎを仮編集で再生し、視聴者が直前に知ったことを使って次を理解できるか確かめる。素材の量産と本編集は、この確認の後に進める。

## 解説・報告型動画の説明順

視聴者が知らない会社、制度、技術、指標を扱う台本では、最初に話の概要と追うべき問いを短く示す。その後は、次の話を理解するために必要な概念や仕組みを、その必要が生じるところで具体例や比較を使って説明する。専門用語は意味が分かる説明の後に導入し、略語と数字を続けて列挙しない。確認できた事実、解釈、未確定の点を区別する。ユーザーが別の話順を指定した場合は、その指定を優先する。

前提を説明せずに専門用語を並べないという方針は、全体に適用する。ただし、各章で「概要→具体例→事実→まとめ」を同じ長さと順番で繰り返す型にはしない。視聴者が直前に分かったことを橋として、次の疑問へ進む。例は論点に合うものを選び、現実の対象との対応と違いを示す。必要な説明を省かず、同じ前提を毎章説明し直すことも避ける。

台本と場面JSONには、各場面が担う問い、読み上げる全文、初出用語の説明、図の段階的な見せ方、理解のための間を対応づける。音声生成や編集の前に、未説明の用語を前提にしていないか、重要な数字を見て考える時間があるか、主題から外れる寄り道が長くないかを通して読む。早口に感じるときは無音を機械的に増やす前に説明の順序と情報量を直す。

## 効果音の設計

効果音を使う場合は、シーン別の配置案を先に書く。絵コンテの段階では発話と演出から音の役割を決め、編集データができたらJSONのオブジェクトID、登場時刻、位置・倍率などのパラメータ変更を配置の基準にする。各効果音を対象の変化の開始または完了に結び付け、同じ役割の変化へ同じ配置規則を適用する。対象一覧と配置済みの音を照合して付け忘れと二重配置を確認し、編集後はJSONから時刻を再計算する。画像と再生は、見え方と音の同期の確認に使う。音源の検索・比較・採用と具体的な手順は [sound-effect-use](../sound-effect-use/SKILL.md) を使う。

## 音声生成

原稿は一文ずつ、そのまま音声合成に渡す。文字数や助詞を目印に文の途中で切らない。

長い文を分ける必要がある場合は、自然に息を継げる位置を文章を読んで決める。

まず冒頭と長い文を作って聞き、読み方・抑揚・つながりを確認してから全編を生成する。不自然な箇所は作り直す。

生成成功や文字起こしだけで、音声を確認したことにしない。

「24文字以内に切り、音声と字幕へ共用する処理」は、この手順に適合しない。

## 音声素材の配置

ナレーション・BGM・効果音は、素材を一つずつ独立したクリップとして、それぞれの音声トラックに配置する。各クリップの音量、開始時刻、長さ、フェードを個別に調整できる編集状態で保存する。音量の指示は、指定された声・曲・効果音のクリップへ反映する。MP4への書き出し時に各トラックをミックスする。

## 字幕

音声が完成してから、その発話に合わせて字幕を作る。字幕の表示単位を音声合成の区切りに使わない。

字幕は音声の意味の切れ目で読みやすい表示単位に分ける。幅、高さ、行数、表示時間を実際の映像サイズで確認し、その場面の図・数値・注目箇所と重ならない場所に置く。位置を全場面で固定する必要はない。字幕のための余白を図に設計する、背景帯を設ける、図を移すなど、場面に合う方法で可読性を確保する。

## 静止画と図の動き

場面ごとに「この発話で視聴者に何を理解してほしいか」「画面のどの要素がその説明に当たるか」「どの順で見せれば理解できるか」を先に決める。台本と場面JSONに、発話区間、対応する図の要素、演出の目的、見せ始めと止める時刻を記録する。対応が曖昧なまま図やアイコンを動かさない。場面数を満たすための同じ演出の配布や、秒数だけを均等に割った切り替えはしない。

画像全体のゆっくりしたズーム・パン、図の一部分の発光、アイコンや矢印の移動などから、その説明に必要なものを選ぶ。動かす対象とレイヤーは場面ごとに決める。例えば横パンは画像外が出ない拡大率と移動範囲を組にし、関係を示す矢印は実際の関係と発話の時刻に沿わせる。既存の図に意味のある矢印や強調があるなら、それを読ませることを優先する。意味を加えない飾りは置かない。

書き出し前に、発話と図の対応、タイトルからの入り方、理解のための間、字幕のはみ出し、文字や重要な要素への重なり、画面外の露出を、音声付きの実フレームと再生で確認する。特に最長の字幕、複数の要素を順に説明する場面、演出の開始・切り替え・終端を確認する。問題があれば規則を一つ足して済ませず、その場面の構成に戻って直す。編集中だけ必要な問いや制作メモは、完成画面から外せるように管理する。

## グラフの表示

グラフは登場時に、棒や面積など値を表す要素を0から目的値まで伸ばして表示する。軸・目盛り・項目名を固定し、値に対応する方向へ基準位置から伸ばす。数値ラベルを動かす場合は図の値と一致させ、到達後は止めて読み取る時間を残す。

比較する棒は同じ尺度と進行率で動かし、長さの比率を保つ。発話に沿って一本ずつ説明する場合も尺度を変えず、表示済みの棒を残す。内訳は合計との関係を保って描き、折れ線は時間軸の順に線を描くなど、グラフの意味に合う方法を選ぶ。

伸びる時間は1.5秒を目安に発話へ合わせる。同時に比較する棒は、それぞれの目的値へ同じ時間で到達させる。画面が切り替わっても同じ棒を残している場合は、毎回0から伸ばし直さず、新しく加わる部分だけを動かす。

軸や文字を含む画像全体の拡大では、このアニメーションを代用しない。値を表す部分を別の部品にするか、描画処理で変化させる。開始・途中・到達後を実フレームと再生で確認し、最終値、比較の比率、ラベル、読み取りの間を確かめる。

## 修正メモからの編集

「さっきの方がよい」「元に戻す」と言われたら、保存版の対象カットを実際に見て現在版と比較し、どの画面を指すか特定する。版番号を推測して戻さない。現在の編集を保存し、指定されたカットの素材・表示順・タイミングだけを復元する。承認済みの別カットを保持し、変更対象外のデータが変わっていないことを比較する。

図は、その説明で追ってほしい関係が一目で分かる構成を選ぶ。手順と繰り返しを説明するなら、一連の流れと戻り先を見せる。具体的な画面やコードを足す場合も、その関係が追えるかを確認する。

1. ユーザーが指定したメモと過去の提案を会話・ファイルから確認し、対象カット、要望、必要素材、編集内容を一覧にする。こちらが提示した内容をユーザーに再提示させない。現在の編集と照合し、未反映・一部反映・反映済みを判断する。
2. 写真や利用画面で実物を知る場面、グラフで数を比較する場面、図で関係や手順を追う場面を選ぶ。文字や汎用アイコンだけで想像させている箇所を探し、説明に必要な画像を取得・生成する。素材は実際に見て選び、実物と説明用の再現画面を区別する。画像の枚数を目標にしない。
3. 素材を揃えてから、主役の大きさ、要素同士の距離、文字との対応、字幕の余白を整える。余白が多い場面は、対象を大きく見せる、必要な具体物や比較を加えるなど、その説明に合う構成へ直す。製品全体を見せる場面では拡大やパンで切り落とさない。
4. 支払いならお金、売買なら現金と権利、効率化なら処理量など、説明する内容から動かす対象を決める。発話の対象が変われば注目箇所も変え、登場・変化・停止の時刻を合わせる。読んで考える時間を残す。
5. メモの各項目を、実際のカットの登場前・変化中・変化後と照合する。どの要望がどの画面へ反映されたかを記録し、画像数や生成成功だけで完了扱いにしない。
6. 変更前を保存してから修正版を別の版として作る。確認後に保存してエディタで開き、編集プロジェクトと書き出したMP4の版・確認範囲を区別して報告する。

画像追加メモを具体的な編集へ対応づける例は [references/revision-editing-example.md](references/revision-editing-example.md) を参照する。例のカット構成や枚数は、別の動画へ固定適用しない。

## 編集環境

### エディタの機能拡張

操作ごとに変更対象と更新が必要な部分を特定し、読み込み済み素材と再生データを再利用する。表示切替は対象レイヤーの可視状態、ミュートは対象トラックの音声出力を直接更新する。全体の再構築は、トラック構成や素材の変更など、再構築が必要な操作で行う。実際の編集プロジェクトで操作の応答時間を確認する。

- プロジェクト: このスキルを含むリポジトリのルート
- 操作仕様: 同プロジェクトの `OPERATIONS.md`
- API仕様: 同プロジェクトの `CONTROL_API.md`
- APIクライアント: リポジトリの `scripts/studio_cli.py`。既定は `http://127.0.0.1:18764`。まず `GET /state` で接続先の編集状態を確認する。
- FFmpeg／FFprobeは不足時にアプリが自動取得する。既存のツールの指定とAPIの接続先の変更はリポジトリのREADMEにある環境変数を使う。素材は編集JSONからの相対パスで保存し、JSONと素材を同じフォルダー構成で移せるようにする。
- 入力素材は PNG/JPG、MP4/MOVなどの動画、16-bit PCM WAV、OBJ、文字、立方体、球体。動画内の音声は取り込まないため、必要ならWAVを別に配置する。3D OBJは現状、マテリアル・テクスチャを再現せず単色で読み込む。カメラは正投影で、位置・拡大率・画面内回転・Z位置を動かせる。この制約を踏まえて場面を設計する。
- `POST /command` の `project.load` でJSONを一括読み込みできる。`clip.add`、`segment.set`、`effect.add`、`transport.seek`、`export.mp4` も使える。APIを使っても、実際のフレームを `GET /frame` で確認する。
- GPU出力は `export.mp4` の `gpu:true` を使う。出力中は `/state` の `status` を見て完了か失敗かを判定する。
- 複数インスタンスが必要な場合は起動時に `TIMELINE_STUDIO_API_PORT` を指定し、既存の編集画面と異なるポートを使う。ユーザーが確認中のアプリを勝手に閉じたり、そこにある未保存の編集を上書きしたりしない。

## グループオブジェクトの使い方

1. タイムラインで映像オブジェクトを `Ctrl + クリック` で2つ以上選び、上部の `グループ化` を押す。WAVはグループ対象外。作成したグループはタイムラインの `G` 行に紫色の帯として表示され、プロジェクトJSONに保存される。
2. 紫色の帯をクリックしてグループを選ぶと、所属する全オブジェクトがタイムラインで強調表示される。帯をダブルクリックするとグループ設定メニューが開く。左右にドラッグすると、各オブジェクトの時間差を保ったまま全員が移動する。グループが6個を超える場合は `G▲` / `G▼` で表示行を切り替える。子オブジェクトの設定欄にある `グループを選択` からも親を選べる。
3. 右側の `グループオブジェクト` 欄で名前、開始秒、X、Y、拡大率、回転を入力し、`グループに反映` を押す。プレビュー上で選択中のグループをドラッグすると、全員の画面位置を一緒に変えられる。グループの表示区間は子の最も早い開始から最も遅い終了までで決まる。
4. 同じ欄の `共通効果` で効果を追加し、効果名を選んで A/B/C/D の値を設定する。有効・無効の切替と削除もここで行う。共通効果は各子オブジェクトへグループ開始時刻を基準に適用され、子ごとの効果も併用できる。
5. `グループ解除` は子オブジェクトを残して親だけを消す。解除すると親の位置・拡大率・回転・共通効果は適用されなくなるので、必要なら解除前に保存する。

APIでは `POST /command` に `{"op":"group.create","ids":["clipIdA","clipIdB"]}` を送り、応答または `GET /state` の `selectedId` から新しいグループIDを得る。移動は `group.move` の `id` と `start`、親の設定は `group.set` の `id`・`field`（`name` / `x` / `y` / `scale` / `rotation`）・`value` を使う。共通効果は `group.effect.add` の `id`・`plugin` で追加し、`group.effect.set` の `id`・`effectId`・`field`・`value` で設定する。削除は `group.effect.delete`、解除は `group.delete`。操作後は `GET /state` で所属と時刻を、`GET /frame` で見た目を確認する。
